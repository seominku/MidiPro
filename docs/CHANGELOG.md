# MidiPro 변경 이력

## 1.3.6 (2026-07)

- **업데이트 내용에 지난 버전 이력을 모두 넣었다**: 1.0(최초 릴리스)·1.1(드럼 에디터·MIDI 클립·어레인지·내장 이펙트 5종·타브)·1.2.1(무거운 VST 크래시 수정·88건반·플러그인 캐시·MIDI 장치 기억 등)까지 사용자용 문장으로 정리했다. 최신이 위로 오는 정렬은 그대로다(테스트가 강제).
- **도움말 > 업데이트 내용으로 열면 전체 이력**을 보여준다(제목도 "MidiPro 변경 이력"으로 바뀐다). 시작할 때 자동으로 뜨는 창은 지난번에 본 버전 이후만 보여준다 — 옛 이력이 매번 다시 뜨지 않는다. 볼 게 없으면 전체를 보여준다(빈 창은 도움이 안 된다).

## 1.3.5 (2026-07)

- **업데이트 내용 창**: 새 버전으로 처음 켤 때 무엇이 바뀌었는지 알려주는 창이 화면 가운데 뜬다. 지난번에 본 버전 이후의 항목을 모두 보여주므로 여러 버전을 건너뛰어도 놓치지 않는다. 도움말 > 업데이트 내용 에서 언제든 다시 볼 수 있다.
- 문구는 `gui/ReleaseNotes.h`에 사용자용으로 따로 적는다 — `docs/CHANGELOG.md`는 개발용이라 내용이 기술적이고 설치본에 따라가지도 않는다. **버전을 올릴 때 여기 `kAppVersion`과 맨 앞 항목도 함께 갱신한다**(설치 스크립트·리소스와 같이). 정보 창의 버전 표시도 이제 이 상수를 쓴다.
- 본 버전은 `settings.ini`의 `last_seen_version`에 남는다. 창을 닫지 않고 앱을 꺼도 종료할 때 기록해서, 같은 알림이 매번 다시 뜨지 않는다.
- 시작 화면이 모달이라 업데이트 창과 겹치면 뒤엣것을 누를 수 없다 — 업데이트 창이 떠 있는 동안은 시작 화면을 미룬다.
- 버전 비교는 문자열이 아니라 숫자로 한다(`1.3.10` > `1.3.9`). 순수 로직이라 단위 테스트한다 — 테스트 스위트 10개 → **11개**(`MidiProNotesTests`).

## 1.3.4 (2026-07)

- **믹스 제어 명령**: 외부 제어에 `mute` / `volume` / `pan` / `gain` / `send`가 생겼다. 트랙 번호 대신 `master`를 주면 마스터를 조절한다(뮤트·센드는 트랙만). 믹서 창에서 만질 때와 같이 되돌리기(Ctrl+Z)가 된다. `status` 응답에도 트랙별 볼륨·팬·게인·센드와 마스터 값이 함께 담긴다.
- **뮤트가 재생 중에 바로 반영된다 (버그 수정)**: 뮤트는 재생 시작 시점의 스냅샷에 들어가서, 재생 중에 뮤트를 눌러도 다음 재생 전까지 소리가 그대로였다. 믹서 창·트랙 뷰 헤더·트랙 목록의 뮤트 체크박스와 외부 제어 명령 모두 지금 위치에서 재생을 다시 걸어 즉시 들리게 했다.

## 1.3.3 (2026-07)

- **플러그인 음색(프리셋) 저장/적용**: 외부 제어에 `presetsave`/`presetload`가 생겼다. 트랙 악기나 트랙 이펙트의 현재 상태를 `.mppreset` 파일로 뽑아 두었다가 다른 트랙·다른 프로젝트에 그대로 적용할 수 있다. 표준 `.vstpreset` 파일도 읽는다.
- `vst/VstPreset.h/.cpp` — 프리셋 파일 ↔ 앱 상태 블롭 변환. 앱의 상태 포맷이 `Comp`+`Cont` 두 덩어리라 `.vstpreset`의 같은 덩어리를 옮겨 담으면 기존 `Vst3Host::loadState`를 그대로 쓸 수 있다. 순수 바이트 처리라 플러그인 없이 단위 테스트한다(Rule 6) — 테스트 스위트가 9개 → **10개**(`MidiProPresetTests`).
  - 테스트가 실제 버그를 잡았다: 덩어리 범위 검사를 `off + size > 파일크기`로 쓰면 파일에 적힌 큰 수가 **넘쳐서** 작은 값으로 되돌아가 검사를 통과했다(= 손상된 파일에서 파일 밖을 가리키는 포인터). 전부 빼기 비교로 바꿨다.
- 한계: MCP가 음색을 "만들어" 내지는 못한다. 플러그인 내부 데이터라 한 번은 앱에서 손으로 잡아야 하고, 그 뒤로는 자동으로 재사용된다. Surge XT 같은 플러그인의 자체 패치(`.fxp`)는 형식이 달라 아직 못 읽는다.

## 1.3.2 (2026-07)

- **외부 제어 통로 (네임드 파이프)**: 실행 중인 앱을 밖에서 조종할 수 있다. `\\.\pipe\MidiPro.Control`에 "명령 인자..." 한 줄을 보내면 JSON 한 줄로 답한다. 명령: `ping status play stop toggle rewind seek tempo save open reload`. MCP 서버가 이걸 써서 **앱을 닫지 않고** 재생/정지·위치 이동·프로젝트 다시 불러오기를 시킨다.
  - 왜 파이프인가: 같은 PC 안에서만 쓰는 통로다. TCP는 방화벽 경고와 외부 노출·포트 선택이 따라온다.
  - **스레드 규칙**: 파이프는 백그라운드 스레드가 받지만 명령은 **UI 스레드가 프레임마다 실행**한다. 버튼을 누른 것과 완전히 같은 코드 경로를 타므로 새로운 경쟁 조건이 없다 — 오디오 스레드는 손대지 않는다. UI가 모달 대화상자에 막힐 수 있어 5초 제한을 두고, 요청마다 번호를 매겨 시간 초과된 요청의 결과가 다음 명령의 응답으로 새지 않게 했다.
  - 두 번째 인스턴스는 통로를 만들지 않는다(`FILE_FLAG_FIRST_PIPE_INSTANCE`) — 앱은 그대로 뜬다.
  - 개인설정에 저장되는 `control_pipe`로 끌 수 있다(기본 켜짐, 시작할 때만 반영).
- **지금 열려 있는 프로젝트 경로를 기억한다** (`AppState::projectPath`). 외부 제어의 `save`/`reload`가 이 경로를 쓴다. 자동 저장본을 복구한 경우는 "작업 중인 파일"이 아니므로 비워 둬서 실수로 덮어쓰지 않게 했다.

## 1.3.1 (2026-07)

- **드럼 샘플 브라우저의 악기 분류 수정**: 이름을 부분 문자열로만 봐서 두 가지 문제가 있었다. (1) **오탐** — 실제 라이브러리의 `HipHop-Bass-MSXII Bottoms Up`이 "Bo**ttom**s" 때문에 '탐' 목록에 섞였다(같은 식으로 "Bell"이 킥, "Abduction"이 킥). (2) **누락** — 라이브러리가 `Ac2 Rd Bell`(라이드), `Ac2 Kik Mt`(킥), `Ac2 Sn Cnt`(스네어)처럼 줄여 쓰는데 `ride`/`kick`만 찾아서 **이 샘플들이 목록에 아예 뜨지 않았다**. 이제 낱말 단위로 보고(앞뒤가 글자면 아님, 복수형 `toms`/`hats`는 허용) `Kik`·`Sn`·`Rd`·`Crsh`·`BD`·`HH`·`OHH` 같은 약어도 인식한다. 약어는 숫자도 경계로 봐서 "3rd"가 라이드로 잡히지 않는다.
- 분류 규칙을 `gui/DrumClassify.h`로 분리해 GUI 없이 단위 테스트한다(Rule 6). 테스트 스위트가 8개 → **9개**가 됐다(`MidiProDrumTests`, 실제 라이브러리 이름을 표본으로 34가지 검사).

## 도구: MCP 서버 (앱 버전과 별개, 2026-07)

- **MidiPro용 MCP 서버 추가 (`mcp/midipro-mcp.mjs`)**: AI 어시스턴트가 `.midipro` 프로젝트를 직접 만들고 편집할 수 있는 도구 9개를 노출한다 — 프로젝트 생성/읽기, 트랙 추가, 노트·코드 진행·드럼 패턴 찍기, 템포 변경, 앱으로 열기, 설치·플러그인 상태 조회. 앱 실행 파일은 프로젝트를 열 때만 쓰고 **앱 코드는 하나도 건드리지 않았다** (`.midipro`가 텍스트 포맷이라 가능).
- 외부 의존성 없음(Node.js만). MCP stdio 전송이 줄바꿈 JSON-RPC라 SDK 없이 구현했다 — npm 설치 없이 배포·유지가 쉽다.
- **모르는 줄은 원문 보존**: 서버가 해석하지 않는 VST 설정·오디오 클립·버전 트리·신스 음색·컨트롤러 매핑 줄을 그대로 유지한다. 편집 시 `<파일>.bak` 백업을 남기고, 임시 파일에 쓴 뒤 원자적으로 교체한다.
- 시간 단위는 박(4분음표), 음높이는 `C4`=60(앱 피아노 롤과 동일). 코드 심볼 30여 종 + 분수코드, GM 드럼 이름 20여 종 지원.
- **MIDI 파일 주고받기 (`midipro_import_midi` / `midipro_export_midi`)**: `.mid`를 가져오면 MIDI의 트랙/채널마다 새 트랙을 만들고(포맷 0은 채널별로 분리), `track`을 주면 기존 트랙 하나에 합친다. ppqn이 다르면 틱을 환산하고 첫 템포를 프로젝트 템포로 반영한다. 내보내기는 포맷 1(트랙 0 = 템포 트랙). 지원 범위를 앱의 `sequencer/SmfFile.cpp`와 같게 맞췄다 — 포맷 0/1, PPQN(SMPTE 거부), 러닝 스테이터스, 템포·트랙 이름 메타, 채널 보이스 메시지(노트 외 CC·피치벤드·프로그램 체인지 포함).
- **트랙 악기·이펙트 (`midipro_set_instrument` / `midipro_add_effect`)**: `tplugin` 줄을 써서 트랙에 VST3 악기와 이펙트를 얹는다(내장 EQ/딜레이/리버브/리미터/컴프도). 앱 UI가 쓰는 값과 같게 맞췄다 — `classIndex = -1`(번들에서 클래스 자동 선택), 내장은 `builtin:<토큰>` 경로. `tplugin`은 `taudio` 블록 앞에 넣어 오디오 클립의 `taudio`→`tgain` 인접을 깨지 않는다. 검증: Surge XT를 세 트랙에 얹고 앱에서 열어 크래시 없이 로드되는 것 확인.
- **드럼 샘플 자동 배정 (`midipro_set_drumkit` / `midipro_list_drumkits`)**: 드럼 트랙이 쓰는 노트를 찾아 `src/Drum` 라이브러리(WAV 4703개, 킷 16개)에서 킥/스네어/햇/탐/심벌을 자동으로 골라 `drumsample` 줄로 적는다. 앱의 자동 분류(`gui/PanelsDrums.cpp classifyDrumPath`)를 옮기되 **자동 배정에 맞게 두 가지를 고쳤다**: (1) 낱말 단위 매칭 — 부분 문자열이면 "Bo**ttom**s Up"이 탐으로, "3**rd**"가 라이드로 잡힌다. 사람이 목록에서 고를 땐 눈으로 걸러지지만 자동은 그대로 집어간다. (2) 0/1 대신 점수 — "snare"가 "rim"보다, "crash"가 막연한 "cymbal"보다 먼저 뽑히고 `Kik`·`Sn`·`Rd`·`Crsh` 약어도 인식한다. 킷 안의 계열(`Acoustic-`/`Urban-`)이 있으면 한 계열로 통일해 잡탕을 막고, 같은 분류에 여러 노트가 걸리면(탐 3개) 후보를 고르게 훑어 서로 다른 샘플이 걸리게 한다.
- 테스트 `mcp/test-midipro-mcp.mjs` — 서버를 실제 프로세스로 띄워 stdio로 대화하며 148가지 검사(프로토콜, 도구별 동작, 오류 처리, 보존, MIDI 왕복, 드럼 분류 오탐, 플러그인 형식, stdout 청결).
- **앱과의 교차 검증**: (1) 실제 앱으로 MCP가 만든 데모 곡을 열어 트랙·노트·템포가 그대로 나오는 것 확인. (2) MCP가 내보낸 `.mid`를 **앱 자신의 `smf::load`로** 읽어 96 BPM·한글 트랙명·드럼 채널 10·노트 56개가 일치함을 확인. (3) 반대로 **앱의 `smf::save`가 쓴 `.mid`를 MCP가** 읽어 140 BPM·트랙명·채널·노트 길이까지 일치함을 확인. (4) 앱 writer가 만들지 않는 러닝 스테이터스는 바이트를 손으로 짜서 별도 검사.
- **앱이 열고 있는 프로젝트 보호**: 이 서버는 파일을 직접 고치는데 앱은 열어 둔 프로젝트를 주기적으로 자동 저장한다 — 겹치면 편집이 통째로 사라진다(개발 중에 여러 번 겪었다). 이제 프로젝트를 고치는 도구 10개가 실행 직전에 `session.lock`(앱이 켤 때 만들고 정상 종료 때 지움)과 `recent.txt` 맨 윗줄을 확인해서, 앱이 **그 프로젝트를** 열고 있으면 **막고**(해결 방법을 알려준다), 다른 프로젝트를 열고 있으면 경고만 붙인다. 확실한 판정은 아니라서 `force: true`로 넘길 수 있고 `MIDIPRO_OPEN_GUARD=off`로 끌 수 있다. 검사는 도구마다가 아니라 디스패처 한 곳에서 하고 `force` 스키마도 자동으로 붙여, 도구가 늘어도 빠뜨리지 않는다. `midipro_status`가 열려 있는 프로젝트를 알려준다.
- 데이터 폴더를 `MIDIPRO_DATA_DIR`로 바꿀 수 있다(테스트를 실제 앱 실행 여부에서 떼어내려고 넣었는데, 이동식 설치에도 쓸 수 있다).
- **실행 중인 앱 제어 (`midipro_transport`)**: 앱 1.3.2의 네임드 파이프에 붙어 재생/정지/토글/처음으로·위치 이동(박)·템포 변경·상태 조회·저장·다시 불러오기를 시킨다. **파일을 고친 뒤 `reload`를 부르면 앱을 껐다 켜지 않고 바로 반영된다** — "닫고 고치고 다시 열기"가 사라졌다. `midipro_status`가 제어 통로가 살아 있는지도 알려준다.
- **플러그인 음색 (`midipro_preset`)**: 앱 1.3.3의 프리셋 명령에 붙어 트랙 악기/이펙트의 음색을 이름 붙여 보관(`save`)하고 다른 트랙·다른 프로젝트에 적용(`load`)한다. 보관함은 `%LOCALAPPDATA%\MidiPro\presets`이고, 표준 `.vstpreset`도 목록에 함께 보여준다. 검증: Surge XT 상태 50397바이트를 트랙 0에서 뽑아 트랙 1에 적용한 뒤 다시 뽑아 **해시가 완전히 같은 것**을 확인했다.
- **믹스 제어 (`midipro_mix`)**: 앱 1.3.4의 믹스 명령에 붙어 뮤트·볼륨·팬·게인·센드를 조절하고 `get`으로 현재 믹스를 한눈에 보여준다(마스터 포함).
- 한계: 음색 자체를 MCP가 만들어 내지는 못한다 — 한 번은 앱에서 손으로 잡아야 한다.

## 1.3.0 (2026-07)

### UI 꾸미기 (밋밋함 개선)
- **DPI 인식 (4K/150% 화면 선명하게)**: 앱이 DPI 비인식이라 150% 화면에서 2560px로 렌더한 것을 Windows가 1.5배 늘려 보여줘 전체가 흐릿했다. 퍼모니터 V2 인식을 켜고, 폰트는 배율만큼 크게 로드(16→24px), 스타일 치수는 `buildStyle` 끝에서 `ScaleAllSizes`, 패널의 고정 픽셀 폭 수백 곳은 `SetNextItemWidth` 일괄 배율 매크로로 해결(물리 좌표로 직접 계산하는 두 곳만 우회). 트랜스포트 표 칸 폭·주요 버튼·피아노 롤 건반 열도 배율 적용. 다른 배율 모니터로 옮기면 창 크기만 따라가고 폰트 배율은 시작 시 값을 유지한다(한계).
- **아이콘 폰트 (Segoe MDL2 Assets 병합)**: Windows 내장 아이콘 폰트를 본문 폰트에 병합해 문자열에 아이콘을 섞어 쓸 수 있다(`gui/Icons.h`). 트랜스포트 재생(▷)·정지(□)·녹음(●)·처음으로(|◁)에 적용 — 문자 도형 대신 진짜 아이콘 글리프라 또렷하다.
- **시작 화면**: 실행하면 "새 곡 / 기타 연습 시작 / 드럼 비트 시작 / 프로젝트 열기" 큰 버튼과 최근 프로젝트 목록을 **화면 정중앙 모달**로 띄운다. 모달이라 어두운 딤이 **시작 화면 뒤에만** 깔린다(ImGui ModalWindowDimBg). "시작할 때 표시" 체크로 끌 수 있고(settings.ini에 저장) ESC/닫기로 넘어간다. ※ 처음에 "중앙정렬이 안 된다"고 판단했던 것은 캡처 도구의 DPI 가상화가 창의 좌상단 일부만 잘라 보여준 오진이었다 — 초록 마커 실측으로 확인 후 바로잡았다.
- **기본 레이아웃**: 오른쪽 도킹 영역의 '기타 도우미'를 빼고 그 자리에 **브라우저**를 넣었다(기타 도우미는 Tool 메뉴로 켤 수 있다).
- **믹서·채널 창에서도 FX 추가 (요청 반영)**: FX 체인 칸에 [+] 버튼 — 트랙 뷰와 같은 메뉴(악기 VSTi / FX / 내장 이펙트 / 프리즈)가 뜬다. 메뉴 코드를 `drawFxAddButton` 하나로 합쳐 세 곳(트랙 뷰·믹서·채널)이 공유한다.

- **트랜스포트 기본 높이 (요청 반영)**: 위 도킹 영역이 16%라 DPI 확대 후 맨 아래 시크 바(|◀ ─── ▶|)가 잘렸다 → 20%로 키워 온전히 보인다.

## 1.2.1 (2026-07)

### 버그 수정
- **트랙을 지웠다 다시 만들면 옛 악기·이펙트·EQ가 남던 문제**: 오디오 엔진은 이것들을 트랙이 아니라 "채널 번호(0~15)"로 들고 있는데, `deleteTrack`이 트랙만 지우고 엔진 채널을 안 비웠다. 같은 채널을 재사용하는 새 트랙에 옛 설정이 그대로 남았다. 이제 지우는 트랙의 채널을 다른 트랙이 안 쓸 때 엔진의 악기·이펙트 체인(EQ 포함)도 함께 비운다.
- **피아노 롤 맨 위 음(C6)에 노트가 안 찍히고, 옮긴 노트가 안 보이던 문제**: 음역 상한 비교가 `note >= 최상단`이라 최상단 음 한 줄이 그리기에서만 빠졌다(줄은 있어 소리는 나고 노트만 안 보임). 양끝 포함(`<=`)으로 바꿔 해결. 겸사겸사 **음역을 표준 88건반(A0~C8)으로 넓혔다** — 처음 열면 가운데 C 근처가 화면 중앙에 오도록 스크롤을 맞춘다.
- **아무것도 선택 안 한 채 Delete를 누르면 트랙이 통째로 지워지던 문제**: 트랙 뷰가 계속 선택된 상태라, 노트를 지우려다 트랙을 날리는 사고가 났다. Delete는 이제 지울 대상(노트·클립·마커 등)이 없으면 아무 일도 하지 않는다. 트랙 삭제는 트랙 헤더 우클릭 메뉴로만 한다.

### 편의 (요청 반영)
- **샘플레이트·버퍼 크기 조절**: `설정 > 개인설정 > ASIO`(WASAPI 기본 출력일 때)에서 버퍼 크기(64~2048)와 샘플레이트(장치가 지원하는 값)를 고른다. 바꾸면 출력을 다시 열고, 올려둔 VST도 새 값으로 다시 준비된다. ASIO는 드라이버가 정하므로 표시만 한다.
- **피아노 롤 88건반**: 위 버그 수정과 함께 A0~C8 전 음역.
- **트랙 뷰 스냅 + 세밀한 격자**: 툴바에 스냅 on/off와 간격(1마디·1/2마디·1박·1/2박·1/4박). 격자 세로선이 그 간격으로 그려지고, 클립을 옮길 때 격자에 맞춰진다(너무 촘촘하면 보조선은 생략).
- **Delete 안전장치**: 위 참고 — 트랙이 실수로 지워지지 않는다.
- **MIDI 파일을 트랙에 직접 불러오기**: 예전엔 `.mid`를 열면 곡 전체가 새로 열렸다. 이제 ① 트랙 위로 **끌어다 놓거나** ② 트랙 헤더 우클릭 > "이 트랙에 MIDI 불러오기"로 그 트랙의 재생 위치부터 노트를 얹는다(ppqn이 다르면 틱 환산). 빈 자리에 떨어뜨리면 새 트랙을 만든다.

### 안정성·편의
- **MIDI 입력/출력 장치를 재시작 때마다 다시 고르던 불편**: 마지막에 쓰던 장치를 `settings.ini`에 남기고 다음 실행 때 자동으로 연다. **번호가 아니라 이름으로** 저장하는 게 요점 — 번호는 장치를 꽂았다 뺐다 하면 밀려서 엉뚱한 게 열린다. 이름이 안 보이면(그 장치를 뽑았으면) 조용히 넘어간다. 열어 두지 않았던 장치는 다음에도 자동으로 열지 않는다(선택만 기억). 소프트 스루 설정도 함께 유지.
- **트랙 [+]를 누를 때마다 한참 기다리던 문제**: "이 플러그인에 악기/이펙트 클래스가 있나"는 플러그인을 **실제로 열어 봐야** 알 수 있는데, Omnisphere급은 한 개에만 몇 초씩 걸린다. 게다가 악기 목록과 이펙트 목록을 따로 거르느라 **같은 플러그인을 두 번** 열고 있었다. 이제 ① 한 번 열어 두 판정을 동시에 하고 ② 결과를 `plugincache.ini`에 남겨 **두 번째 실행부터는 아예 열지 않는다.** 플러그인을 업데이트하면 파일 크기·수정 시각이 달라지므로 그 항목만 자동으로 다시 조사한다. 판정이 잘못됐을 때를 위해 VST3 창에 **[다시 조사]** 버튼을 뒀다.
- **가상악기를 넣은 상태에서 내장 신디사이저를 켜면 프로그램이 꺼지던 문제**: 오디오 스트림이 새로 열릴 때 장치가 원하는 **샘플레이트와 버퍼 크기로 바뀌는데**(예: 44100/256 → 48000/480), 이미 올라와 있는 VST에게는 그 사실을 알려 주지 않았다. 플러그인은 자기가 `setupProcessing`으로 약속받은 조건대로 내부 버퍼를 잡아 두므로, 다른 조건으로 불리면 오작동하거나 그대로 죽는다. `Vst3Host::reconfigure()`를 추가해 스트림이 열릴 때마다(WASAPI·ASIO 모두) 올라와 있는 모든 플러그인(전역 악기·이펙트·트랙 악기·트랙 FX)을 새 조건으로 다시 준비한다. 값이 같으면 아무 일도 하지 않고, 음색(상태)은 유지된다.
- **한글 사용자 이름에서 깨질 뻔한 경로 버그**: 플러그인 캐시 경로를 좁은 `getenv`로 읽고 있었다. 그 값은 ANSI 코드페이지 바이트인데 UTF-8로 해석하면 사용자 이름이 한글일 때 경로가 깨진다(`core/PathUtf8.h`에 이미 적혀 있던 함정). 와이드 `_wgetenv`로 읽어 `pathToUtf8`로 바꾸도록 고쳤다.
- **무거운 VST 악기(Omnisphere·Keyscape·Trilian)에서 오류창 없이 프로그램이 꺼지던 문제**: 원인은 **멀티아웃 악기의 출력 버스 처리**였다. 이들은 메인 외에 파트별 보조 출력 버스를 여럿 갖는데, 우리는 `ProcessData`에 버스를 **하나만** 넘기면서 `numOutputs=1`로 뒀다. VST3 규격상 호스트는 플러그인이 가진 **모든 버스**에 대해 `AudioBusBuffers`를 줘야 하고 플러그인은 그 개수만큼 배열을 훑는다 — 없는 원소를 읽으니 잘못된 포인터에 오디오를 써서 프로세스가 통째로 죽었다. 이제 버스 개수만큼 자리를 만들고 0번만 실제 출력에 연결하며, 나머지는 버리는 버퍼로 채운다. 버스별 채널 수도 `getBusInfo`로 **실제 값**을 물어 쓴다(`setBusArrangements`가 거부돼도 어긋나지 않게). 스피커 배치도 버스 개수만큼 넘긴다. 함께 고친 것 — 규격상 필수인데 빠져 있던 **`setComponentHandler`**(노브를 잡는 순간 호스트를 부르는 플러그인이 죽을 수 있다)와, 안 쓰는 보조 버스 비활성화.
- **크래시 기록기 (`core/CrashLog`)**: VST 플러그인은 우리 프로세스 안에서 돌기 때문에 플러그인이 무너지면 우리도 창 하나 없이 사라진다. 이제 마지막 순간에 `%LOCALAPPDATA%\MidiPro\crash.log`와 `crash.dmp`를 남기고 안내 창을 띄운다. 로그에는 **예외 종류·주소·범인 모듈(어느 DLL인지)·접근 종류**와 "하던 작업"(예: `VST 악기 로드: ...Omnisphere.vst3`)이 찍혀 원인 지목이 가능하다. `SetUnhandledExceptionFilter` + `set_terminate` + `_set_invalid_parameter_handler` + `_set_purecall_handler`를 모두 걸고, CRT가 예외를 삼키지 않도록 `SEM_NOGPFAULTERRORBOX`를 해제한다. 검증: 전용 하네스로 접근 위반·C++ 예외를 실제로 일으켜 로그 내용(한글 포함)과 덤프 생성을 확인했다. `MIDIPRO_NO_CRASH_DIALOG` 환경변수로 무인 실행 시 창만 끌 수 있다(기록은 그대로).

### 편곡
- **MIDI 클립**: 노트를 블록으로 묶어 트랙 뷰에서 이동(가로/세로=트랙 간)·복제·범위 조절·삭제 (Ctrl+D/Del). 노트 On/Off 짝을 스팬 단위로 보존.

- **벨로시티 도구**: 램프(크레센도)/랜덤/일괄 (벨로시티 레인 우클릭).
- **성능**: 노트 추출 캐시(편집 스탬프) — 큰 곡에서도 트랙 뷰/드럼 에디터가 부드럽다.
- **구간 복제**: 마커 우클릭 → 구간 전체(모든 트랙)를 뒤에 삽입.
- **어레인지 뷰**: 구간 블록 드래그로 곡 구조 재배열 + 점프/복제/삭제.
- **멀티 아웃**: 스템 내보내기에 리턴 리버브 스템 + 스템 리미터 옵션.
- **타임스트레치 품질**: 정규화 상관 탐색 + 등파워 크로스페이드로 이음새 클릭 감소, 드래그 중 배율 표시.
- **휠 체계 통일**: 휠=확대, Shift+휠=세로, Ctrl+휠=가로 (트랙 뷰/피아노 롤/드럼).
- **템포 램프**: 템포 지점 사이 점진 가속/감속 (마커 라벨 `>>`).
- **곡 미니맵**: 트랙 뷰 상단 전체 보기 + 클릭 이동.
- **기타 트랙 + 타브 악보 창**: 6줄 타브(표준 튜닝) 자동 표기, 최저 프렛 줄 배정, 재생 따라가기.
- **타브 가져오기**: 텍스트 타브(ASCII TAB) 붙여넣기 → 노트 변환 삽입 (여러 단 이어붙임, 두 자리 프렛, 한 칸=8/16/32분 선택).
- **PDF 악보 가져오기**: 조판 PDF에서 6줄 타브 보표를 직접 찾아 노트로 (자체 PDF 파서 — Flate 압축·RC4 암호화·Type0 폰트 해독, 벡터 가로줄로 보표 검출, 기타 1·2 파트 분리). 스캔(이미지) 악보는 미지원.
- **PDF 음표(리듬) 인식**: 타브에 붙은 기둥·빔·부점을 읽어 음길이를 복원 (빔 0=4분, 1=8분, 2=16분, 부점 ×1.5). 슬래시(/)는 직전 코드 다시 치기로 처리하고, 마디선마다 시각을 하드 리셋해 오차가 누적되지 않는다.
- **타브 가져오기 동작 정리**: PDF에 파트가 여럿이면(기타 1·2) **파트마다 트랙을 따로 만들어** 넣고, 다시 가져오면 이전 가져오기 구간을 지우고 덮어쓴다 (겹쳐 쌓이지 않는다). 같은 시각의 중복 노트도 제거해 소리가 두 배로 커지지 않는다.
- **리듬 정확도(중요)**: 프렛 숫자 뒤의 **흰색 가림막 사각형**을 빔으로 오인해 8분이 16분·32분으로 압축되던 문제 — 채우기 색을 추적해 흰 도형을 제외한다. 빔 판정도 밴드 방식 대신 "기둥의 빔 쪽 끝 근처의 얇은 검정 사각형"으로 바꿔 보표 안쪽에 빔을 그리는 조판(musx류)도 정확히 읽는다.
- **타브 창 다중 트랙**: [표시 트랙]으로 여러 트랙을 골라 보표를 위아래로 쌓아 본다 (기타 1·2 동시 보기). 트랙 뷰·채널 창에서 **Shift+클릭**으로도 추가/제거 (클릭 순서 = 보표 순서). PDF에서 파트 2개를 가져오면 자동으로 둘 다 띄운다. 트랙 이름은 스크롤을 따라오고 유형 색으로 표시.
- **트랙 유형 배지**: 트랙 뷰·채널 창·믹서의 트랙 이름 앞에 [드럼](주황)/[기타](초록) 표시 — 일반 트랙과 한눈에 구분된다.
- **입력 지연 보정**: 입력 장치 버퍼 지연(일반 WASAPI 입력은 100ms+)을 자동 차감 + 수동 오프셋 슬라이더 + Δ 진단 표시(최근 타격과 가장 가까운 악보 음의 시간차 — 판정창을 벗어나도 보임) 추가. 지연 때문에 타격이 판정창 밖으로 밀려 "후보 없음 x"만 뜨던 문제.
- **스트로크 중복 판정 수정**: 스트로크는 줄마다 어택이 시차로 나서 온셋이 여러 번 잡히는데, 각각이 따로 판정돼 x/빨간 표시가 코드 음 수만큼 중복으로 찍히던 문제. 한 음은 한 번만 판정하고(실패해도 소비), 판정 직후 0.18초 안의 잔여 어택은 같은 스트로크로 묶어 무시. RtAudio WASAPI가 지연값을 100ns 단위로 잘못 보고하는 버그 방어(0.35초 초과 값 무시)도 추가.
- **자동 맞춤 버튼**: 연습 툴바(오프셋 옆)에 추가. 재생 정지 상태에서 누르면 킥 4번 카운트인 → 100BPM 햇 클릭 16번이 울리고, 클릭에 맞춰 3번줄 개방현(G)을 치면 박마다 타격 시각과 검출 여유 배율을 재서 오프셋(중앙값)과 감도(하위 25% 여유 × 0.45)를 자동 설정. 16번 중 12번 미만 감지면 실패로 안내. 수동 슬라이더는 그대로 유지되고 결과가 슬라이더에 반영된다.
- **연습 창 트랜스포트**: 재생/정지·처음으로·**템포**·**메트로놈**(+클릭 음량)·박자표·카운트인을 창 안에 추가 — 연습이 이 창 하나에서 완결된다.
- **연습 창 루프**: 마디 단위 시작~끝 입력 + **[현재 마디]**(재생 위치의 마디 하나를 즉시 루프 — 막히는 마디에서 바로) + **[+2마디]**(되면 조금씩 넓히기) + 반복 횟수 표시. 루프 구간을 타브에 파란 띠/음영으로 그린다.
- **[템포에 맞추기] 버튼이 다시 활성화되지 않던 문제 수정**: 만들어둔 스트레치를 "곡 템포"로만 기억해서, **원본 BPM**을 고치면 필요 배율이 달라졌는데도 버튼이 비활성 상태로 남았다. 기억하는 값을 **배율(원본BPM/곡BPM)** 로 바꿔 둘 중 뭘 고쳐도 잡히게 했다.
- **설치 프로그램 (Inno Setup)**: `installer\MidiPro.iss` → `MidiPro-Setup-1.1.0.exe`(약 3MB). 모든 사용자용(`C:\Program Files\MidiPro`, UAC 필요), 시작 메뉴·바탕 화면 바로가기, `.midipro` 파일 연결(선택), **「설정 > 앱 > 설치된 앱」에 등록되어 거기서 제거** 가능. 제거는 설치한 파일만 지우고 `%LOCALAPPDATA%\MidiPro`(설정·테마·자동저장)는 남기며, 마지막에 한 번 물어본다(기본 = 남기기). 드럼 샘플 1.35GB는 제외 — 대신 앱이 `%LOCALAPPDATA%\MidiPro\Drum`도 찾도록 해서 관리자 권한 없이 나중에 넣을 수 있게 했다. 설치본은 Program Files에 있어 상대 경로 `src/Drum`에 쓰기가 안 되기 때문이다. **`.midipro` 파일 연결을 위해 명령줄 인자로 프로젝트 열기**를 추가했다(`CommandLineToArgvW` → 기존 `recentOpenPath` 경로 재사용). 검증: 계정 전용 사본으로 컴파일해 무인 설치→실행→무인 제거를 실제로 돌려 파일·바로가기·레지스트리 등록/삭제와 사용자 데이터 보존을 확인. **두 가지 결함을 잡았다** — ① 제거 확인 창에 `MsgBox`를 써서 무인 제거가 영영 멈췄다(→ `/SUPPRESSMSGBOXES`를 존중하는 `SuppressibleMsgBox`로 교체, 2초에 종료), ② `.midipro` 확장자 키가 빈 껍데기로 남았다(→ `uninsdeletekeyifempty` 추가).
- **버튼·탭·제목 표시줄에 이미지 입히기 (모든 창 공통)**: ImGui에는 위젯 스킨 개념이 없고 버튼 호출부만 수백 군데라, 호출부를 고치는 대신 **그린 뒤에 바꾸는** 방식을 택했다 — ① 이미지를 폰트 아틀라스 안에 자리를 받아 써넣고(`AddCustomRect` + `ImFontAtlasTextureBlockQueueUpload`), ② `ImGui::Render()` 뒤에 정점을 훑어 버튼/탭/제목 색으로 칠해진 덩어리를 찾아 그 덩어리의 바운딩 박스 기준으로 UV를 다시 매긴다. 위젯 사각형은 원래도 아틀라스 텍스처를 쓰므로 **드로우 콜을 쪼갤 필요가 없고**, 모서리 둥글기와 안티에일리어싱 테두리가 그대로 남는다. 올림/눌림 상태는 같은 이미지의 밝기만 달리해 눌리는 느낌을 유지한다. 창별로 나누지 않은 이유 — 창마다 버튼 모양이 다르면 산만하고 아틀라스 자리도 그만큼 더 든다. **색 충돌 대책**: 색을 열쇠로 삼으므로 버튼 색이 슬라이더 손잡이와 완전히 같으면 엉뚱한 위젯까지 이미지가 됐다(실제로 발생). 팔레트를 만들 때 열쇠 색 11개를 1/255씩만 어긋나게 해 유일하게 만들고(`makeSkinKeysUnique`), 그래도 창별 팔레트끼리 겹치는 색은 아예 열쇠에서 제외한다(안 입히는 쪽이 잘못 입히는 것보다 낫다). 아틀라스가 커지면 자리·픽셀이 날아가므로 매 프레임 좌표를 확인해 다시 써넣는다. GIF는 첫 장만 사용. **슬롯마다 왼/오/위/아래 오프셋(px)** 을 줘서 이미지를 붙일 범위를 위젯 사각형에서 넓히거나(넘쳐 잘림) 좁힐 수 있고, 좁힌 쪽은 UV를 물려 가장자리 색이 늘어난다. 저장 키는 `skinimg <슬롯> <진하기> <경로>` + `skinofs <슬롯> <좌> <우> <상> <하>` — 경로가 줄 끝이라 오프셋은 별도 줄로 뺐고, 없으면 0이라 옛 파일과 호환된다. 테마 공유 파일에도 함께 담긴다.
- **배경 이미지 여러 장 겹치기(레이어)**: 전체 배경·창별 배경 모두 이미지를 여러 장 쌓을 수 있다(예: 벽지 + 구석 로고). 한 장짜리 필드(`bgImage`/`bgImageOpacity`/…)를 `std::vector<BgLayer>` 하나로 바꾸고, 장마다 진하기·표시 방식·크기·위치·표시 여부를 따로 갖는다. 그리기는 목록 순서대로 아래→위. 창별 배경은 예약이 하나였던 것을 목록(`addPendingWindowBackground`)으로 바꿔 한 창에 여러 장이 겹치게 했다. 텍스처도 레이어 목록과 1:1로 맞추고(`syncLayers`), 파일이 사라진 레이어는 목록에서 자동으로 빠진다. 저장은 새 키 `bglayer`/`winbglayer`(경로는 줄 끝이라 공백 허용)이고, 옛 키(`bgimg*`/`winbg*`)로 저장된 파일은 읽을 때 한 장짜리 레이어로 자동 승격된다. UI는 목록(켜기/끄기 · ▲▼ 순서 · 삭제) + 선택한 장의 세부 조절이며 전체/창별이 `drawBgLayers` 하나를 공유. 검증: 2장 왕복(순서·개별 설정·꺼둔 상태 포함), 공유 파일에 2장 모두 담겼다가 원본이 사라진 PC에서 바이트까지 복원, 옛 형식 마이그레이션, 실제 앱에서 두 장이 겹쳐 그려지는지 화면으로 확인.
- **배경 이미지가 다시 켰을 때 안 보이던 버그 수정**: 테마 파일에 저장된 개별 색(`col` 줄)이 마지막에 통째로 덮어써지면서 **패널 불투명도로 낮춰둔 알파(1이 아님)까지 1로 되돌려** 배경이 창에 완전히 가려졌다. 한 번이라도 테마가 저장된 뒤(=사실상 항상) 재현되던 문제. 이제 `col`을 되살린 뒤 배경이 비쳐야 하는 색들(WindowBg·ChildBg·Tab·MenuBar 등 `kPanelBgCols`)의 알파만 테마 값으로 되돌려, 색조는 저장된 것을 쓰되 투명도는 테마가 이기게 했다.
- **배경 이미지 '직접 지정' 배치**: 표시 방식에 네 번째 모드를 추가해 **크기(원본 대비 배율)와 가로/세로 위치**를 직접 정할 수 있다. 위치는 CSS `background-position`과 같은 방식(0=왼쪽/위, 0.5=가운데, 1=오른쪽/아래)이라 이미지가 영역보다 클 때는 "보여줄 부분"을 고르는 팬 역할을 한다. 전체 배경·창별 배경 모두 지원하며 UI는 `drawBgPlacement` 하나를 공유. 파라미터가 늘어 `BgPlacement` 구조체로 묶었다. 저장은 새 키(`bgimgplace`/`winbgplace`)로 분리해 옛 테마 파일이 그대로 읽힌다(경로가 줄 끝인 `winbg` 형식을 건드리지 않기 위함).
- **테마 탭 단계적 공개 (초보 진입 문제)**: 기능을 쌓기만 하고 입구를 안 만들어 처음 여는 사람에게 선택지가 한꺼번에 쏟아지던 문제. 3단계로 나눴다 — **기본**(프리셋 + 밝기 + 되돌리기만), **자세히**(강조색·글자·모서리·패널 불투명도·전체 배경), **고급**(창별 오버라이드·내 테마 저장/주고받기·개별 색 편집). 기존 기능은 하나도 없애지 않고 접어두기만 했다. 프리셋 버튼에 그 테마의 실제 색을 칠하고(배경=버튼색, 강조색=아래 띠, 글자=그 테마 글자색) **[기본으로 되돌리기]**(색·창별·배경 전부 초기화, 저장한 '내 테마'는 보존)를 추가했다.
- **테마 주고받기 (한 파일로 내보내기/가져오기 + 드래그&드롭)**: 남이 만든 테마를 손 안 대고 쓰게 하는 게 목적. 걸림돌은 배경 이미지가 **절대 경로**로 저장돼 다른 PC에선 조용히 사라진다는 점이었다 → 내보낼 때 이미지 자체를 base64로 파일 안에 담고 경로를 `@img:N`으로 치환, 가져올 때 `themes/assets`에 풀어 그 PC 경로로 되돌린다(`exportTheme`/`importTheme`). `imgdata` 줄은 기존 로더가 무시하므로 형식 호환이 유지된다. `.mptheme`를 창에 **끌어다 놓으면 즉시 적용** + 목록에 추가. 별도 외부 툴을 만들지 않은 이유 — 테마를 *쓰는* 쪽은 앱만 있으면 되고 *만드는* 쪽은 앱이 이미 편집기라, 공유에 필요한 건 툴이 아니라 **파일의 이식성**이었다. 검증: 보낸 사람 원본 이미지를 지운 뒤 가져와도 이미지가 복원되고 바이트까지 일치, 이미지 없는 테마·망가진 파일도 안전 처리.
- **창별 배경 이미지/GIF**: 창마다 다른 이미지를 그 창 안쪽에만 깔 수 있다(진하기·표시 방식도 창별). ImGui가 창 배경을 스스로 그리므로, 그리기 직전에 배경을 "예약"하고 각 창의 주 `Begin()` 직후 `drawPendingWindowBackground()`가 창 자신의 draw list에 먼저 그려 넣는 방식 — 내용은 그 위에 얹히고 창 경계에서 정확히 클립된다. 예약은 한 창만 소비하므로 그 창이 여는 보조 창(타브 가져오기·자동 맞춤 등)에는 깔리지 않고, 창이 접혀 안 그려졌으면 예약을 흘리지 않게 비운다. theme.ini에 `winbg` 줄(경로는 줄 끝까지라 공백 허용)로 저장. 전체 배경 그리기와 창 배경 그리기는 `drawImageInRect` 하나를 공유한다.
- **내 테마 (이름 붙여 저장/불러오기)**: 전체 색 + 창별 오버라이드 + 배경 이미지 설정을 통째로 `%LOCALAPPDATA%\MidiPro\themes\<이름>.mptheme`에 저장하고 목록에서 불러오기/삭제. 불러올 때는 창별 설정을 먼저 비워 파일에 없는 창이 전체 테마를 상속하게 하고, 배경 이미지도 함께 다시 올린다(파일이 없으면 설정만 해제). 기존 `saveTheme`/`loadTheme`을 경로만 바꿔 재사용 — 형식이 theme.ini와 같다. 왕복 검증 하네스로 전체 파라미터·공백 있는 경로·창별 오버라이드·"저장 안 한 창은 상속"·`effectiveParams` 상속 규칙까지 확인.
- **창별 스타일 오버라이드**: 창 18개를 각각 다르게 꾸밀 수 있다. ImGui 스타일이 전역이라, `App.cpp`에 모여 있는 draw 호출을 `pushWindowStyle`/`popWindowStyle`로 감싸 그리기 직전에 스타일을 바꿔 끼우고 끝나면 되돌린다(스타일 구조체 통째 교체 — 색 55개를 Push/Pop 하는 것보다 싸다). **항목별 상속**: 체크한 항목만 덮어쓰고 나머지는 전체 테마를 따라가므로, 전체 테마를 바꾸면 커스텀 안 한 부분이 같이 따라온다. 설정은 theme.ini에 `winov` 줄로 저장되며 켜진 창만 기록해 옛 파일과 호환된다. 별도 디자인 툴을 만들지 않은 이유 — 앱 자체가 실시간 프리뷰라 실물 위에서 고치는 편이 정확하고, 없던 건 편집 능력이 아니라 "적용 범위"였다.
- **테마 프리셋 확장 (4 → 14종)**: 다크·라이트·미드나잇·바이올렛에 더해 에메랄드·앰버·크림슨·오션·슬레이트·노르드·솔라라이즈드·고대비·로즈·샌드 추가. 프리셋을 `ThemePreset` 표(이름+생성 함수)로 모아 UI가 표를 돌기만 하게 했다 — 앞으로 프리셋 추가는 Theme.cpp 한 곳만 고치면 되고, 버튼은 창 폭에 맞춰 자동 줄바꿈된다. 프리셋을 눌러도 사용자가 깔아둔 배경 이미지 설정은 유지한다.
- **배경 이미지·움직이는 GIF**: 창 전체 뒤에 이미지를 깔 수 있다. 디코딩은 Windows 내장 WIC(`windowscodecs`)를 써서 외부 라이브러리 없이 PNG·JPG·BMP·GIF를 지원하고, **애니메이션 GIF는 프레임별 지연·부분 갱신(디스포절)까지 규격대로 합성**해 DX11 텍스처로 올린다(`gui/BackgroundImage.h/.cpp`). 표시 방식 3종(채우기/맞추기/타일 — ImGui 샘플러가 CLAMP라 타일은 반복 그리기로 구현), 이미지 진하기 조절, **패널 불투명도**(`panelAlpha`) 슬라이더로 창 배경을 반투명하게 만들어 배경이 비치게 한다. 배경이 있을 때는 도킹 호스트를 `PassthruCentralNode`로 뚫어 가운데 빈 영역이 배경을 덮지 않게 했다. 설정(경로·진하기·표시 방식·패널 불투명도)은 theme.ini에 저장돼 다시 켜도 유지되고, 파일이 사라졌으면 설정을 자동 해제한다.
- **드럼 패턴 자동 생성**: 박자표(4/4·3/4·6/8)와 스타일(기본 락·8비트 팝·발라드)·마디 수를 고르면 드럼을 자동으로 채운다. 순수 로직 `sequencer/DrumPattern.h`(헤더온리) — 8분음표 격자로 킥/스네어/햇/크래시 배치를 정의하고 ppqn으로 환산, 마디마다 반복. 유닛 테스트(testDrumPattern: 4/4·3/4·6/8 배치 위치·개수, 2마디 오프셋, 발라드 크래시 없음, 무효 입력). 드럼 창 [패턴 채우기] 팝업 — 재생 헤드 마디부터 채우고 그 구간을 먼저 비운다(eraseMidiRange), 박자표 자동 설정 옵션.
- **코드 찾기 기능**: 멜로디 MIDI → ① 조성 판별(Krumhansl-Schmuckler 프로파일 상관계수, 길이 가중 히스토그램) → ② 다이어토닉 코드 7개 생성(간격에서 메이저/마이너/디미니시 자동 판정, 장·단조 공용) → ③ 마디별 코드 추천(코드 구성음의 길이 합 점수, 동점 시 I·IV·V 우선, 스무딩, 짧은 경과음 제외). 순수 로직은 `sequencer/ChordFinder.h`(헤더온리, GUI 무관)로 분리하고 유닛 테스트(testChordFinder) + 실제 진행 3종 하네스로 검증(Let It Be=C G Am F, G장조 I-IV-V-I, Am 진행). 피아노 롤 툴바에 [코드 찾기] 버튼, 결과를 마디 위에 표시.
- **피아노 롤 노트에 음이름 표시**: 노트 블록 위에 음이름(C4·F#3 등)을 얹어 무슨 음을 찍었는지 바로 보이게 했다. 블록이 글자보다 넓고 행 높이가 글자를 담을 때(줌이 충분할 때)만 그려 좁을 땐 생략, 선택된(밝은) 노트엔 어두운 글자로 대비. 기존 `noteName()` 헬퍼 재사용.
- **ASIO 재개폐로 시스템이 멈추던 치명 버그 수정**: 트랙마다 ASIO 버튼이 있어 다른 트랙에서 켜면 `stopAsio`(WASAPI 출력 복구)→`startAsio`(다시 WASAPI 닫고 ASIO 열기)로 **ASIO 드라이버를 순식간에 닫았다 다시 열었다** — 실시간 우선순위 콜백과 맞물려 드라이버가 커널째 멈추면 재부팅/전원차단까지 났다. ASIO는 단일 듀플렉스 스트림이므로, 이미 켜져 있으면 재시작하지 않고 **소유권(모니터 트랙)만 넘기게** 했다(`startAsio`가 같은 장치면 채널 모드만 갱신하고 스트림은 유지). 트랙 뷰·연습 창 양쪽의 ASIO 버튼 모두 수정.
- **입력 채널 선택이 반영되지 않던 버그 수정(입력2인데 입력1도 섞임)**: 연습 창의 입력 채널 콤보가 트랙 필드만 바꾸고 엔진에 반영하지 않아, ASIO 스트림이 계속 이전 모드(기본 1+2 합침)로 돌았다. 콤보 변경 시 그 트랙이 입력 중이면 `setInputChannelMode`를 즉시 호출하고, ASIO는 콜백이 `m_inMode`로 채널을 live 선택하므로 스트림 재시작 없이 반영한다.
- **연습 창에 오디오 레인(파형) 추가 + 반주를 트랙 클립으로 전환**: 파형 없이 숫자로 시작 오프셋을 맞추는 건 사실상 불가능했다. 이제 타브 위에 트랙별 오디오 클립이 파형으로 보이고, **드래그로 위치를 맞춘다**(자유 이동, Shift=마디 스냅). 반주는 전용 슬롯이 아니라 **선택한 연습 트랙 위의 보통 클립**이 되어 트랙 볼륨·뮤트·FX·녹음 클립과 같은 체계로 다뤄진다. [템포에 맞추기]는 원본에서 다시 늘려 트랙 위 클립을 교체하되 맞춰둔 위치(startTick)는 유지한다. 렌더링은 기존 `drawClipBlock`/`drawWaveform` 공용 함수를 재사용.
- **연습 반주 (MP3/WAV) + 템포 연동**: 연습 창에 반주 슬롯 추가 — 음원을 물리고 **원본 BPM**을 입력하면, 곡 템포를 낮춘 뒤 **[템포에 맞추기]** 로 음정을 유지한 채(WSOLA) 반주를 같이 늘린다. 느리게 연습 → 원래 속도로 올리는 훈련용. 상태 표시(초록=맞음 / 주황=몇 배 필요), 0.5~2배 밖이면 `(!)` 음질 경고, **시작 오프셋**(+=늦게 시작, -=인트로 건너뜀)으로 반주 첫 박을 악보 1마디에 맞춤, 볼륨·음소거·빼기. 스트레치는 항상 원본에서 다시 계산한다(겹쳐 걸면 음질이 무너지므로). 반주는 트랙 클립이 아니라 창 전용 슬롯이고, 아무 트랙도 안 쓰는 버스로 나가 기타 FX 체인을 타지 않는다. 합성 검증: 164 BPM 원본을 120/100/90/82 BPM으로 맞췄을 때 길이 오차 <2%, 박 오차 <3%, 음정 편차 0센트.
- **'기타 연습' 전용 창 (타브 악보 창 대체)**: 연습 기능이 곡 작업용 MIDI 기능과 섞여 헷갈리던 문제. `Tool > 기타 연습`으로 열리며, 창 하나에 연습 트랙 목록 + 타브 악보 + 판정 + 자동 맞춤이 모두 들어간다.
  - **연습 트랙은 MIDI 트랙과 완전히 별개**: `Track::practice` 플래그(프로젝트에 `tprc`로 저장). 트랙 뷰·믹서·피아노 롤 고스트·드럼 에디터·내보내기 미리보기·VST 출력 선택 등 MIDI 쪽 화면에는 나타나지 않고, 연습 창은 연습 트랙만 다룬다. 선택 상태도 `practiceTrack`으로 분리돼 두 창이 서로를 흔들지 않는다. (저장은 song.tracks를 공유하므로 재생·녹음·ASIO·프로젝트 저장이 그대로 동작)
  - **연습 창 왼쪽 트랙 패널**: 트랙 추가/삭제, 선택, Shift+클릭으로 여러 트랙 동시 표시(*), 트랙별 **● 녹음**(오디오 입력 → 클립), **[ASIO]** 저지연 모니터 토글, 입력 채널 선택, 볼륨 + **레벨 미터**, **FX 체인**.
  - **FX 체인 공용화**: 트랙 뷰에 인라인으로 박혀 있던 FX 체인 박스(~190줄)를 `drawTrackFxChain()`으로 추출해 트랙 뷰와 연습 창이 공유한다 (복제 없음). 연습 창은 `withInstrument=false`로 악기/프리즈 없이 이펙트만 — 앰프 시뮬·오버드라이브로 연습 톤을 만들고 ASIO 모니터로 들을 수 있다.
  - **레벨 미터**: 툴바의 입력 미터를 ProgressBar → 정식 미터 위젯(dB 스케일·피크 홀드·클립 래치)으로 교체하고, 트랙마다 버스 미터를 추가. 툴바=드라이(판정이 듣는 신호), 트랙=포스트 FX로 역할이 다르다.
  - **입력 자동 열기**: [연습]을 누르면 입력 스트림이 자동으로 열린다(ASIO 우선, 실패 시 일반 입력) — 예전에는 별도로 ASIO 모니터나 입력 모니터 창을 켜야 판정이 동작했다. 열지 못하면 툴바에 "입력 안 열림!" 경고를 띄운다.
  - 연습 트랙 녹음이 MIDI 쪽 `selectedTrack`을 바꾸던 문제 수정 — 트랙 뷰에 보이지도 않는 트랙이 선택돼 피아노 롤이 엉뚱한 트랙을 편집하게 됐다.
  - 타브 가져오기가 연습 트랙을 대상으로 동작 — 파트가 여럿이면 연습 트랙을 늘리고, 재가져오기 시 연습 트랙 안에서만 그룹 꼬리표를 찾는다.
- **코드 인식 검증·개선**: 풀 오픈 코드(C 5음·G 6음), 코드 진행(C→G→Am→C, 뮤트 없이), 120BPM 8분 스트러밍 ×8, 디스토션까지 합성 검증 스위트 추가. 발견·수정 2건 — (1) 코드 동료 음의 배음이 기대 음의 반음 이웃 대역에 정당하게 얹히는 경우(G코드에서 B2의 3배음 F#4) 이웃 비교가 정상 음을 기각 → 같은 코드 구성음의 배음(1~6차)은 이웃 비교에서 제외. (2) 베이스 배음이 기본음 대역을 지배해 에너지가 한 대역에 몰리면 "배음 2개" 규칙이 진짜 음을 기각 → 기본음 대역이 서 있으면 배음 1개여도 인정. 결과: C 5/5, G 5/6(줄 1개는 위상 간섭으로 표시 누락 가능하나 코드 판정은 통과), 진행 4/4, 스트러밍 7~8/8, 디스토션 걸린 연주도 판정 통과. 알려진 한계: 디스토션 "입력"(앰프/페달을 거쳐 입력)은 인터모듈레이션으로 헛 크레딧 가능 — 드라이 직결 권장 유지.
- **자동 맞춤 전용 창**: 버튼이 바로 측정을 시작하는 대신 전용 창을 연다 — 안내문 + 칠 것을 보여주는 미니 타브(4마디×4박, 3번줄 0), 카운트인 진행 점 4개, 지금 칠 박 노란 테두리, 박별 감지 결과 초록/빨강 실시간 표시, 측정 시작/중단 버튼과 수동 감도·오프셋 슬라이더까지 한곳에. 재생 중이면 측정 시작이 자동으로 정지시킨다.
- **연습 판정 엔진 전면 교체 — 악보 주도 청취(score-driven listening)**: 온셋 감지(소리에서 타격 순간을 맹목적으로 찾기)는 폴리포닉 기타에서 본질적으로 불안정해 폐기. 대신 각 악보 이벤트마다 그 시각 주변(±140ms)에서 "기대 음의 배음 에너지가 85ms 전 대비 1.9배 이상 뛰고, +85ms 뒤에도 유지되며(스치는 픽 잡음 배제), 배음 2개 이상이 서 있고(남의 배음 겹침 배제), 반음 이웃보다 뚜렷한가"를 직접 확인(noteRiseAt, Hann창 Goertzel — 사각창 누설로 1.7반음 옆 음이 헛 배음을 만들던 것도 수정). 잔향·맥놀이·스트로크 중복·아르페지오가 원리적으로 문제가 안 되고, 과잉 스트럼은 무시(헛 x 없음). 1차에서 못 찾으면 +450ms까지 재탐색해 늦은 타격을 BAD로 처리하되 Δ를 자동 지연 보정에 공급. 합성 검증 5종(아르페지오 4/4·코드 3/3·같은 코드 4연타·틀린 코드/무음 무크레딧·+200ms 늦은 타격 감지) 전부 통과. 입력 링 16k→128k 샘플.
- **온셋 감지기 로그-플럭스 개편**: 빠른 아르페지오에서 첫 음 빼고 인식이 안 되던 문제. 선형 스펙트럴 플럭스는 링잉의 맥놀이(20~190)와 약한 플럭(38~99)이 구분이 안 되고, 에너지 상승 게이트(×1.25)가 울리는 코드 위의 약한 플럭(+10~20%)을 차단했다. 로그-플럭스(새 배음의 "출현"에 반응, 기존 배음의 출렁임에는 무반응, 잡음 바닥은 중앙값 빈×8로 차단)로 바꾸고 에너지 조건은 "붕괴 아님"(×0.70)으로 완화 — 합성 검증: 링잉 플럭스 ≤11 vs 어택 35~467, 아르페지오 4/4 감지. 잔향 판별도 음정 인지형으로: 직전 스트로크에 없던 새 음이 잡히거나 근처 악보 음이 실제로 울리기 시작했으면(아르페지오) 잔향으로 버리지 않는다. 포락선 게이트는 30%로 완화(약한 플럭 통과). 유닛 테스트 합성 스트럼에 픽 트랜지언트 추가(실제 픽킹에 반드시 있는 브로드밴드 어택 — 감지기가 같은 코드 재타격을 이것으로 구분).
- **연습 판정 대개편(잔향·지연)**: 코드 잔향의 맥놀이가 수백 ms 간격으로 온셋을 재발화시켜 x가 계속 찍히던 문제를 3중으로 차단 — (1) 입력 피크 포락선 게이트(최근 피크의 55% 미만 "온셋"은 잔향으로 무시, 시정수 0.8초; 연속 스트럼·100ms 재타격·약한 스트럼은 통과함을 합성 신호로 검증), (2) 직전 스트로크 구성음이 아직 절반 이상 울리면 잔향으로 무시(1.5초), (3) 헛스트로크 묶음 창 0.18→0.3초. **입력 지연 자동 학습**: 타격 Δ의 중앙값이 일관되게 치우치면(4회 이상, 3/4가 ±60ms 안) 자동 오프셋에 흡수 — 슬라이더를 손대지 않아도 몇 번 치면 맞는다. 첫 보정이 100ms를 넘으면 그동안의 엉터리 점수는 리셋.
- **코드 판정 경주 버그(치명)**: 코드 검증(어택 +135ms)이 돌기 전에 '놓친 음 스캔'이 그 코드를 먼저 소비해, 정상 스트로크가 항상 "후보 없음 BAD"가 되던 문제 — 놓침 판정에 검증 지연만큼 유예를 둔다. 음정불명 'x' 표시도 6번줄이 아닌 레인 중앙으로.
- **코드 검증 강화**: 기타 튜닝 오차(±30센트) 흡수 탐색 + 창 분해능보다 반음 간격이 좁은 배음(저음 기본음)을 판별에서 제외 — 판별을 희석시키던 원인. 디튠된 디스토션 파워코드 유닛 테스트로 검증.
- **연습 모드 인식 엔진 재설계**: 스트로크/연타를 놓치던 문제 —
  - 어택 감지를 RMS 상승비에서 **스펙트럴 플럭스(FFT) + 적응 임계값 + 이동평균 에너지 상승 게이트**로 교체 (100ms 간격 연타, 코드 지속음의 맥놀이 오검까지 유닛 테스트로 검증)
  - 입력을 GUI 프레임과 무관하게 **읽기 커서로 5ms 단위 빠짐없이** 처리 — 창이 밀려도 어택을 놓치지 않고, 온셋의 샘플 위치로 판정 타이밍의 지연을 수학적으로 보정
  - 툴바에 **입력 레벨 미터 / "입력 없음" 경고 / 감도 슬라이더** 추가
- **연습 레인 = 6줄 미니 타브**: 친 음이 악보와 같은 줄 위치에 찍히고, 코드는 구성음별로 울림(판정색)/빠짐(빨강)이 줄 단위로 보인다.
- **연습 모드 코드 판정**: 단선율 검출이 안 되는 스트로크는 "기대-음 검증"(Goertzel 스펙트럼 대조, 반음 이웃 비교)으로 코드 구성음을 하나하나 확인 — 디스토션에도 강하다. 스트로크 한 번이 코드 전체를 소비하도록 고쳐 구성음이 놓침 처리되던 버그도 해결.
- **연습 모드 (리듬 게임)**: 타브 창 [연습] — 기타 입력을 실시간 피치 분석(NSDF 자기상관, 20센트 정확도 검증)해 악보와 비교 판정 (GREAT ±60ms / GOOD ±140ms / BAD). 정확도 %, 판정 색 표시, 맨 아래 '연주' 줄에 친 음 기록. 놓친 음은 BAD, 되감기/루프 시 재판정.
- **음악적 뉘앙스 계층**: 가져온 노트가 더는 "전부 벨로시티 100, 길이 균일"이 아니다.
  - 박 위치 강약: 마디 첫 박(106) > 박(97) > 8분 엇박(88) > 16분 엇박(80)
  - 뮤트 점(·) = 절반 길이 + 여리게, X(데드) = 퍼커시브 척(30% 길이, vel 52)
  - **이음줄 인식**: 같은 프렛이면 타이(한 음으로 병합), 다른 프렛이면 해머링/풀링/슬라이드 레가토(앞 음을 꽉 채우고 뒷 음은 여리게)
  - 꾸밈음(작은 숫자)은 리듬 칸에서 제외 — 박자를 밀어내지 않는다
- **마디 앞 쉼표(픽업) 감지**: 마디 첫 음의 가로 위치가 기본 여백(자가 보정)보다 뚜렷이 오른쪽이면 앞 쉼표로 처리 — 마디 끝 픽업 프레이즈가 첫 박으로 당겨지던 문제.
- **인쇄 마디 번호 검증**: 프렛/운지 숫자를 마디 번호로 오인해 단이 엉뚱한 위치에 앉던 문제 — "세어온 위치 ±4마디 이내 + 단조 증가"일 때만 신뢰한다.
- **뮤트 점(·)과 부점 구분**: 숫자 위에 찍히는 뮤트 표시를 부점으로 읽어 8분이 부점8분으로 늘어지던 문제 — 부점은 "숫자와 같은 줄, 바로 오른쪽"일 때만 인정한다.
- **쉼표 감지**: 같은 마디 안에서 음 사이 가로 간격이 앞 음의 길이보다 뚜렷이 크면 그만큼 쉼표로 처리한다 (8분 단위 반올림). 쉼표가 있는 마디에서 뒷 음들이 앞으로 당겨지던 문제.
- **보표 가운데 떠 있는 짧은 기둥 인식**: 뮤트 스트로크처럼 보표 안쪽에 짧게 그려지는 기둥을 놓쳐 그 단이 통째로 비던 문제 — 기둥 판정을 "보표에 닿는 세로선"으로 일반화하고, 빔은 기둥 양 끝 중 많이 붙은 쪽으로 센다.
- **운지(줄) 그대로 표시**: 같은 음이라도 2번줄 9프렛/1번줄 4프렛처럼 운지가 여럿이다 — 가져올 때 악보가 지정한 줄을 힌트로 저장해(프로젝트에 함께 저장) 타브 창이 악보 그대로의 운지로 표시한다. 힌트 없는 노트(직접 그린 것)는 기존처럼 최저 프렛 자동 배정.
- **템포 자동 설정**: 악보의 ♩=164 표기를 읽어 곡 BPM에 반영 ("= 164"가 한 덩어리든, '='와 숫자가 따로든, 숫자가 한 글자씩 쪼개져 있든 처리).
- **가져오기 트랙 그룹**: PDF에서 만든 트랙에 (악보 이름, 파트 번호) 꼬리표를 붙여 프로젝트에 저장 — 같은 악보를 다시 가져오면 트랙이 늘어나지 않고 기존 트랙을 덮어쓴다. 트랙 이름도 "곡명 · 기타 N"으로 묶인다.
- **마디 반복 기호(𝄎) 펼치기**: "앞 N마디를 그대로" 기호를 읽어 그 마디들을 복사해 채운다 (기호 글리프를 악보에서 자동 식별).
- **타이밍 정확도(중요)**: 인쇄된 마디 번호를 읽어 단마다 시각을 절대 좌표로 못 박는다. 그동안 기타가 쉬어서 타브 보표가 아예 없는 단(과 쉼표만 있는 보표)을 통째로 건너뛰어, 그 뒤 마디가 전부 앞으로 당겨지고 있었다.
- **위로 뻗은 기둥 인식**: 빔이 보표 위에 그려진 음(기둥이 보표 꼭대기에서 시작)을 0.3pt 차이로 놓쳐 통째로 빠지던 문제.
- **짧은 기둥 인식(musx류)**: 보표 안에서 시작해 바닥선을 1pt 남짓만 지나는 기둥을 놓치던 문제 — 그 단 전체가 무음이 됐다.
- **큰 단(보컬+기타1·2 = 보표 5개) 묶기**: 단 연결선이 길다는 이유로 페이지 테두리로 오인해 단이 쪼개지고 마디가 이중 계산되던 문제. 마디 수도 오선보(기둥이 마디선으로 둔갑)가 아닌 타브 보표에서만 센다.
- **도돌이표 펼치기**: 굵은 세로줄 + 점 두 개로 반복 시작(‖:)/끝(:‖)을 읽어 반복 구간을 두 번 연주하도록 펼친다. 모든 파트를 같은 순서로 다시 깔아 파트가 어긋나지 않는다. (볼타·D.C./D.S.는 미지원)
- **파트 나누기 정확도**: 보표 간격 추측 대신 **마디선이 두 보표를 관통하는지**로 한 단을 판정한다 (6페이지짜리 악보에서 파트를 10개로 잘못 나누던 문제).
- **박자표 3/4·6/8 지원**: 마디 그리드·마디 번호·루프·구간 복제·내보내기가 모두 박자표를 따른다 (그동안 4/4 고정이었다). PDF에서 박자표를 읽어 자동 설정하고, 6/8은 8분음표를 한 박으로 센다.

### 믹싱
- **내장 이펙트 5종**: EQ(3밴드)·딜레이·리버브·컴프레서·리미터 — VST와 같은 체인.
- **사이드체인 덕킹**: 내장 컴프레서에 키 트랙 지정 (킥으로 베이스 덕킹).
- **모니터 이펙트**: ASIO 모니터가 트랙 FX 체인을 탄다 (녹음은 드라이).
- **기본 EQ**: 새 트랙마다 자동 장착, 믹서/채널 창에서 Bass/Middle/Treble 노브.
- **마스터 리미터**: 기본 켜짐, GR 표시, 내보내기 반영.
- **센드/리턴**: 트랙별 Send 노브 → 공용 리버브.

### 재생/입력
- **카운트인**: 재생 시작 전에도, 루프 되감김마다도.
- **Shift+Space** 현재 마디부터 재생, **Ctrl+Space** 처음으로.
- **MIDI 장치 없이 녹음**: 건반 연주(Z~M)만으로 녹음 시작.
- **피치 벤드 레인** (피아노 롤), **CC 오토메이션** (트랙 뷰).
- **벨로시티 도구**: 크레센도/랜덤/일괄 (벨로시티 레인 우클릭).

### 기타
- 채널 창 마커 리스트(클릭=양쪽 뷰 이동), 드럼 트랙/채널 창 기본 도킹, 프로젝트 패키지 내보내기(샘플 동봉), 프로그램 아이콘/정보 창, 한글 사용 설명서.
